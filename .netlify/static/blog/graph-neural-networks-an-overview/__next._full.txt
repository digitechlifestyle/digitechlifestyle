<p>Over the past decade, we’ve seen that Neural Networks can perform tremendously<br />
well in structured data like images and text. Most of the popular models like<br />
<a href="https://theaisummer.com/Neural_Network_from_scratch_part2/" target="_blank" rel="noopener">convolutional networks</a>, <a href="https://theaisummer.com/Bitcon_prediction_LSTM/" target="_blank" rel="noopener">recurrent</a>, <a href="https://theaisummer.com/Autoencoder/" target="_blank" rel="noopener">autoencoders</a> work very well on data that have<br />
a tabular format like a matrix or a vector. But what about unstructured data?<br />
What about Graph data? Is there a model that can learn efficiently from them?<br />
Probably you guessed it from the title. The answer is</p>
<h2 id="graph-neural-networks">Graph Neural Networks.</h2>
<p>Graph Neural Networks were introduced back in 2005 (like all the other good<br />
ideas) but they started to gain popularity in the last 5 years. The GNNs are<br />
able to model the relationship between the nodes in a graph and produce a<br />
numeric representation of it. The importance of GNNs is quite significant<br />
because there are so many real-world data that can be represented as a graph.<br />
Social networks, chemical compounds, maps, transportation systems to name a few.<br />
So let’s find out the basic principles behind GNNs and why they work.</p>
<p>Let’s define our basic problem first: We want to map a given graph to a single<br />
label, which can be a numeric value, a class or whatever really. In other<br />
words:</p>
<div class="math">
<p>&nbsp;</p>
<p>F( Graph )=embedding F(\text { Graph })= embedding<span class="katex-html" aria-hidden="true"><span class="base"><span class="mord mathnormal" style="margin-right: 0.13889em;">F</span><span class="mopen">(</span><span class="mord text"><span class="mord"> Graph </span></span><span class="mclose">)</span><span class="mrel">=</span></span><span class="base"><span class="mord mathnormal">e</span><span class="mord mathnormal">m</span><span class="mord mathnormal">b</span><span class="mord mathnormal">e</span><span class="mord mathnormal">d</span><span class="mord mathnormal">d</span><span class="mord mathnormal">i</span><span class="mord mathnormal">n</span><span class="mord mathnormal" style="margin-right: 0.03588em;">g</span></span></span></p>
</div>
<p>And we want to find the function F. For example, imagine that each graph is a<br />
chemical compound or a molecule and the label is the likelihood that this<br />
molecule can be used to produce a certain drug. If we have a way to extract the<br />
label from every graph, we essentially found a way to predict which molecules<br />
are more likely to be used in a drug. Cool, right?</p>
<p>How do we do this? We already know a type of Neural Network that can be used on<br />
Graphs (sort of). If you think about it, recurrent neural networks can operate<br />
on a special type of graph. A chained graph (This a graph that is basically a<br />
line). Time series are actually chained graphs, where each timestamp is a node<br />
followed by the next timestamp.</p>
<p>So, in fact, we can build a network where each graph node is a recurrent unit<br />
(<a href="https://theaisummer.com/Bitcon_prediction_LSTM/" target="_blank" rel="noopener">LSTM</a> or something else) and the information of the node is an embedding that<br />
will be transferred through the chain (like a message). And because the units<br />
are all recurrent, the information won’t be lost when the embedding travels<br />
through the graph. It is our familiar Recurrent neural networks. Exactly the<br />
same as the ones used in language translation and the other natural language<br />
processing applications.</p>
<p>We can of course extend this idea to proper graphs and we get this:</p>

<p>This slide is taken from an awesome <a href="http://talk" target="_blank" rel="noopener">talk</a> about GNNs by Microsoft<br />
Research. Let’s see for a moment what is going on here.</p>
<p>Each orange triangle used to be graph node and it’s now replaced by a recurrent<br />
unit. The envelopes represent the embeddings of the nodes that will travel<br />
through the graph. Each graph edge is also replaced by a Neural network to<br />
capture the information of the edge (its weight).</p>
<p>Now for the learning part. At a single time step, each node pulls the embedding<br />
from all its neighbors, calculates their sum and passes them along with its<br />
embedding to the recurrent unit, which will produce a new embedding. This new<br />
embedding contains the information of the node plus the information of all the<br />
neighbors. In the next time step, it will also contain the information of its<br />
second-order neighbors. And so on and so on. The process continues until every<br />
node knows about all the other nodes in the graph.  Each one of the embeddings<br />
has now information from all the other nodes. The final step is to collect all<br />
embeddings and add them, which will give us a single embedding for the whole<br />
graph.</p>
