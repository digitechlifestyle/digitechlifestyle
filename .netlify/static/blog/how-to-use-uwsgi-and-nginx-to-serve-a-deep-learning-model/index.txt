<p>Preparing for a Machine Learning Engineer position? This article was written for you! Why?</p>
<p>Because we will build upon the Flask prototype and create a fully functional and scalable service. Specifically, we will be setting up a Deep Learning application served by <strong>uWSGI</strong> and <strong>Nginx</strong>. We will explore everything step by step: from how to start from a simple Flask application, wire up <strong>uWSGI</strong> to act as a full web server, and hide it behind <strong>Nginx</strong> (as a reverse proxy) to provide a more robust connection handling. All this will be done on top of the deep learning project we built so far that performs semantic segmentation on images using a custom Unet model and Tensorflow.</p>
<p>Up until this moment on the series, we have taken a colab notebook, converted to a highly optimized project with <a href="https://theaisummer.com/unit-test-deep-learning/" target="_blank" rel="noopener">unit tests</a> and performance enhancements,<a href="https://theaisummer.com/training-cloud/" target="_blank" rel="noopener"> trained the model</a> in Google cloud, and <a href="https://theaisummer.com/deploy-flask-tensorflow/" target="_blank" rel="noopener">developed a Flask prototype</a> so it can be served to users.</p>
<p>We will enhance upon this Flask prototype and build a fully functional and scalable service.</p>
<h2 id="what-is-uwsgi">What is uWSGI?</h2>
<p>According to the official website:</p>
<blockquote><p>uWSGI is an application server that aims to provide a full stack for developing and deploying web applications and services.</p></blockquote>
<p>Like most application servers, it is language-agnostic but its most popular use is for serving Python applications. uWSGI is built on top of the WSGI spec and it communicates with other servers over a low-level protocol called uwsgi.</p>
<p>Ok this is very confusing and we need to clarify this up, so let&#8217;s start with some definitions.</p>
<ul>
<li><strong>WSGI</strong> (Web Server Gateway Interface): An <strong>interface</strong> specification that defines the communication between a web server and a web application. In simple terms, it tells us what methods should be implemented to pass requests and responses back and forth between the server and the application. It is basically an API interface that&#8217;s being used to standardize communication and it is part of Python’s standard library.</li>
<li><strong>uWSGI</strong>: An <strong>application</strong> server that communicates with applications based on the WSGI spec and with other web servers over a variety of other protocols (such as HTTP). Most of the times it acts like a middleware because it translates requests from a conventional web server into a format that the application understands (WSGI)</li>
<li><strong>uwsgi</strong>: a low-level/binary <strong>protocol</strong> that enables the communication between web servers. uwsgi is a wire protocol that has been implemented by the uWSGI server as its preferred way to speak with other web servers and uWSGI instances. In essence, it defines the format of the data sent between servers and instances.</li>
</ul>
<p>Let&#8217;s look at the whole picture now: We have our software exposed to a web app using Flask. This application will be served using the uWSGI server and it will communicate with it using the WSGI spec. Moreover, the uWSGI server now will be hidden behind another web server (in our case Nginx) with whom it will communicate using the uwsgi protocol. Does it make sense? Seriously I don’t know why they named all these with the same initials!</p>

<p>If I were you, I would still have two more questions.</p>
<p>Why do we need the uWSGI server in the first place (isn’t Flask enough?) and why do we need another web server such as Nginx in front of uWSGI?</p>
<p>And they&#8217;re both valid.</p>
<h2 id="why-do-we-need-uwsgi-isnt-flask-adequate">Why do we need uWSGI? Isn’t Flask adequate?</h2>
<p>While Flask can act as an HTTP web server, it was not developed and optimized for <strong>security</strong>, <strong>scalability</strong>, and <strong>efficiency</strong>. It is rather a framework to build web applications as explained in the <a href="https://theaisummer.com/deploy-flask-tensorflow/" target="_blank" rel="noopener">previous article</a>. uWSGI on the other hand was created as a fully functional web server and it solves many problems out of the box that Flask doesn’t even touch.</p>
<p>Examples are:</p>
<ul>
<li><strong>Process management</strong>: it handles the creation and maintenance of multiple processes so we can have a concurrent app in one environment, and is able to scale to multiple users.</li>
<li><strong>Clustering</strong>: it can be used in a cluster of instances</li>
<li><strong>Load balancing</strong>: it balances the load of requests to different processes</li>
<li><strong>Monitoring</strong>: it provides out of the box functionality to monitor the performance and resource utilization</li>
<li><strong>Resource limiting</strong>: it can be configured to limit the CPU and memory usage up to a specific point</li>
<li><strong>Configuration</strong>: it has a huge variety of configurable options that gives us full control over its execution</li>
</ul>
<p>Having said that, let’s inspect our next tool: Nginx.</p>
<h2 id="what-is-nginx-and-why-do-we-need-it">What is Nginx and why do we need it?</h2>
<p>Nginx is a high-performance, highly scalable, and highly available web server (lots of highly here). It acts as a load balancer, a reverse proxy, and a caching mechanism. It can also be used to serve static files, to provide security and encryption on the requests, to rate-limit them and it supposedly can handle more than <strong>10000 simultaneous connections</strong> (actually in my experience it’s not so much of an assumption). It is basically uWSGI on steroids.</p>
<p>Nginx is extremely popular and is a part of many big companies&#8217; tech stack. So why should we use it in front of uWSGI? Well, the main reason is that we simply want the best of both worlds. We want those uWSGI features that are Python-specific but we also like all the extra functionalities Nginx provides. Ok if we don&#8217;t expect our application to be scaled to millions of users, it might be unnecessary but in this article series, this is our end goal. Plus it&#8217;s an incredible useful knowledge to have as a Machine Learning Engineer. No one expects us to be experts but knowing the fundamentals can’t really hurt us.</p>
<p>In this example, we&#8217;re going to use Nginx as a reverse proxy in front of uWSGI. A reverse proxy is simply a system that forwards all requests from the web to our web server and back. It is a single point of communication with the outer world and it comes with some incredibly useful features. First of all, it can balance the load of million requests and distribute the traffic evenly in many uWSGI instances. Secondly, it provides a level of security that can prevent attacks and uses encryption in communications. Last but not least, it can also cache content and responses resulting in faster performance.</p>

<p>A sample config file (app.ini) can look like this:</p>
<p><span class="token punctuation" style="color: #f8f8f2;">[</span><span class="token plain">uwsgi</span><span class="token punctuation" style="color: #f8f8f2;">]</span></p>
<p><span class="token plain">http </span><span class="token operator">=</span> <span class="token number">0.0</span><span class="token number">.0</span><span class="token number">.0</span><span class="token punctuation" style="color: #f8f8f2;">:</span><span class="token number">8080</span></p>
<p><span class="token plain">module </span><span class="token operator">=</span><span class="token plain"> app</span><span class="token punctuation" style="color: #f8f8f2;">.</span><span class="token plain">service</span></p>

<p><span class="token plain">die</span><span class="token operator">&#8211;</span><span class="token plain">on</span><span class="token operator">&#8211;</span><span class="token plain">term </span><span class="token operator">=</span><span class="token plain"> true</span></p>
<p><span class="token plain">chdir </span><span class="token operator">=</span> <span class="token operator">/</span><span class="token plain">home</span><span class="token operator">/</span><span class="token plain">aisummer</span><span class="token operator">/</span><span class="token plain">src</span><span class="token operator">/</span><span class="token plain">soft_eng_for_dl</span><span class="token operator">/</span></p>

<h2 id="wire-up-nginx-as-a-reverse-proxy">Wire up Nginx as a reverse proxy</h2>
<p>The next task in the todo list is to wire up the Nginx server which again is as simple as building a config file.</p>
<p>First, we install it using “apt-get install”</p>
<p><span class="token plain">sudo apt</span><span class="token operator">&#8211;</span><span class="token plain">get install nginx</span></p>
<pre class="prism-code language-python" style="color: #f8f8f2; background-color: #282a36;"></pre>
<p>Next, we want to create the config file that has to live inside the “/etc/nginx/sites-available” directory (if you are in Linux) and it has to be named after our application.</p>
<p><span class="token plain">sudo nano </span><span class="token operator">/</span><span class="token plain">etc</span><span class="token operator">/</span><span class="token plain">nginx</span><span class="token operator">/</span><span class="token plain">sites</span><span class="token operator">&#8211;</span><span class="token plain">available</span><span class="token operator">/</span><span class="token plain">service</span><span class="token punctuation" style="color: #f8f8f2;">.</span><span class="token plain">conf</span></p>
<pre class="prism-code language-python" style="color: #f8f8f2; background-color: #282a36;"></pre>
<p>Then we create a very simple configuration file that contains only the absolute minimum to run the proxy. Again, to discover all the available configuration options, be sure to check out the official documentation.</p>
<p><span class="token plain">server </span><span class="token punctuation" style="color: #f8f8f2;">{</span></p>
<p><span class="token plain"> listen </span><span class="token number">80</span><span class="token punctuation" style="color: #f8f8f2;">;</span></p>
<p><span class="token plain"> server_name </span><span class="token number">0.0</span><span class="token number">.0</span><span class="token number">.0</span><span class="token punctuation" style="color: #f8f8f2;">;</span></p>
<p><span class="token plain"> location </span><span class="token punctuation" style="color: #f8f8f2;">{</span></p>
<p><span class="token plain"> include uwsgi_params</span><span class="token punctuation" style="color: #f8f8f2;">;</span></p>
<p><span class="token plain"> uwsgi_pass unix</span><span class="token punctuation" style="color: #f8f8f2;">:</span> <span class="token operator">/</span><span class="token plain">home</span><span class="token operator">/</span><span class="token plain">aisummer</span><span class="token operator">/</span><span class="token plain">src</span><span class="token operator">/</span><span class="token plain">soft_eng_for_dl</span><span class="token operator">/</span><span class="token plain">app</span><span class="token operator">/</span><span class="token plain">service</span><span class="token punctuation" style="color: #f8f8f2;">.</span><span class="token plain">sock</span><span class="token punctuation" style="color: #f8f8f2;">;</span></p>
<p><span class="token punctuation" style="color: #f8f8f2;">}</span></p>
<p><span class="token punctuation" style="color: #f8f8f2;">}</span></p>
<pre class="prism-code language-python" style="color: #f8f8f2; background-color: #282a36;"></pre>
<p>Here we tell Nginx to listen to the default port 80 for requests coming from the server located in 0.0.0.0 The location block is identifying all requests coming from the web to the uWSGI server by including “uwsgi_params” which specifies all the generic uWSGI parameters, and “uwsgi_pass” to forward them to the defined socket.</p>
<p>What socket you may wonder? We haven’t created a socket. That’s right. That’s why we need to declare the socket in our uWSGI config file by adding the following 2 lines:</p>
<p><span class="token plain">socket </span><span class="token operator">=</span><span class="token plain"> service</span><span class="token punctuation" style="color: #f8f8f2;">.</span><span class="token plain">sock</span></p>
<p><span class="token plain">chmod</span><span class="token operator">&#8211;</span><span class="token plain">socket </span><span class="token operator">=</span> <span class="token number">660</span></p>
<pre class="prism-code language-python" style="color: #f8f8f2; background-color: #282a36;"></pre>
<p>This instructs the server to listen on the 660 socket. And remember that Nginx speaks with you uWSGI through the socket using the uwsgi protocol.</p>
<blockquote><p><strong>Socket</strong>: A web socket is a bidirectional secure connection that enables a two-way interactive communication session between a user and a client. That way we can send messages to a server and receive event-driven responses without having to poll the server for a reply.</p></blockquote>
<p>Finally, we enable the above configuration by running the below command that links our config in the “sites-available” directory with the “sites-enabled” directory</p>
<p><span class="token plain">sudo ln </span><span class="token operator">&#8211;</span><span class="token plain">s </span><span class="token operator">/</span><span class="token plain">etc</span><span class="token operator">/</span><span class="token plain">nginx</span><span class="token operator">/</span><span class="token plain">sites</span><span class="token operator">&#8211;</span><span class="token plain">available</span><span class="token operator">/</span><span class="token plain">service </span><span class="token operator">/</span><span class="token plain">etc</span><span class="token operator">/</span><span class="token plain">nginx</span><span class="token operator">/</span><span class="token plain">sites</span><span class="token operator">&#8211;</span><span class="token plain">enabled</span></p>
<pre class="prism-code language-python" style="color: #f8f8f2; background-color: #282a36;"></pre>
