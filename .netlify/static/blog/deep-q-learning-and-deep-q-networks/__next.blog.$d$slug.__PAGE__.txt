<p>The journey to Reinforcement learning continues… It’s time to analyze the<br />
infamous Q-learning and see how it became the new standard in the field of AI<br />
(with a little help from neural networks).</p>
<p>First things first. In the <a href="https://theaisummer.com/Reinforcement_learning/" target="_blank" rel="noopener">last post</a> , we saw the basic concept<br />
behind Reinforcement Learning and we frame the problem using an agent, an<br />
environment, a state (S), an action(A) and a reward (R). We talked about how the<br />
whole process can be described as a Markov Decision Process and we introduced<br />
the terms Policy and Value. Lastly, we had a quick high-level overview of the<br />
basic methods out there.</p>
<p>Remember that the goal is to find the optimal policy and that policy is a<br />
mapping between state and actions. So, we need to find which action to take<br />
while we stand in a specific state in order to maximize our expected reward. One<br />
way to find the optimal policy is to make use of the value functions (a<br />
model-free technique).</p>
<p>And here we will get to the new stuff. In fact, there are two value functions<br />
that are used today. The state value function V(s) and the action value function<br />
Q(s, a) .</p>
<ul>
<li>State value function: Is the expected return achieved when acting from a<br />
state according to the policy.</li>
<li>Action value function: Is the expected return given the state and the<br />
action.</li>
</ul>
<p>What is the difference you may ask? The first value is the value of a particular<br />
state. The second one is the value of that state plus the values of all the<br />
possible actions from that state.</p>

and we update the Q accordingly. In first, randomness will be a key player but<br />
as the agent explores the environment, the algorithm will find the best Q value<br />
for each state and action. Can we describe this mathematically?</p>

<p>Thank you Richard E. Bellmann. The above equation is known as the Bellman<br />
equation and plays a huge part in RL today’s research. But what does it state?</p>
<p>The Q value, aka the maximum future reward for a state and action, is the<br />
immediate reward plus the maximum future reward for the next state. And if you<br />
think about it, it makes perfect sense. Gamma (γ) is a number between <!-- -->[0,1]<!-- --> and<br />
its used to discount the reward as the time passes, given the assumption that<br />
action in the beginning, are more important than at the end (an assumption that<br />
is confirmed by many real-life use cases). As a result, we can <strong>update the Q<br />
value iteratively</strong>.</p>
<p>The basic concept to understand here is that the Bellman equation relates<br />
states with each other and thus, it relates Action value functions. That helps<br />
us iterate over the environment and compute the optimal Values, which in turn<br />
give us the optimal Policy.</p>
<p>In its simplest form, Q values is a matrix with states as rows and actions as<br />
columns. We initialize the Q-matrix randomly, the agent starts to interact with<br />
the environment and measures the reward for each action. It then computes the<br />
observed Q values and updates the matrix.</p>

<h2 id="exploration-vs-exploitation">Exploration vs Exploitation</h2>
<p>The algorithm, as described above, is a <a href="https://www.guru99.com/greedy-algorithm.html" target="_blank" rel="noopener">greedy algorithm</a>, as it always chooses the<br />
action with the best value. But what if some action has a very small probability<br />
to produce a very large reward? The agent will never get there. This is fixed by<br />
adding random exploration. Every once in a while, the agent will perform a<br />
random move, without considering the optimal policy. But because we want the<br />
algorithm to converge at some point, we lower the probability to take a random<br />
action as the game proceeds.</p>
<h2 id="why-going-deep">Why going Deep?</h2>
<p>Q learning is good. No one can deny that. But the fact that it is ineffective in<br />
big state spaces remains. Imagine a game with 1000 states and 1000 actions per<br />
state. We would need a table of 1 million cells. And that is a very small state<br />
space comparing to chess or Go. Also, Q learning can’t be used in unknown states<br />
because it can’t infer the Q value of new states from the previous ones.</p>
<p>What if we approximate the Q values using some machine learning model. What if<br />
we approximate them using neural networks? That simple idea (and execution of<br />
course) was the reason behind <a href="https://techcrunch.com/2014/01/26/google-deepmind/" target="_blank" rel="noopener">DeepMind acquisition</a> from Google for 500 million<br />
dollars. DeepMind proposed an algorithm named Deep Q Learner and used it to <a href="https://deepmind.com/research/publications/playing-atari-deep-reinforcement-learning" target="_blank" rel="noopener">play<br />
Atari</a> games with impeccable mastery.</p>
<h2 id="deep-q-learning">Deep Q Learning</h2>
<p>In deep Q learning, we utilize a neural network to approximate the Q value<br />
function. The network receives the state as an input (whether is the frame of<br />
the current state or a single value) and outputs the Q values for all possible<br />
actions. The biggest output is our next action. We can see that we are not<br />
constrained to Fully Connected Neural Networks, but we can use Convolutional,<br />
Recurrent and whatever else type of model suits our needs.</p>

<h2 id="experience-replay">Experience Replay</h2>
<p>Experience replay is a concept where we help the agent to remember and not forget its previous actions by replaying them. Every once in a while, we sample a batch of previous experiences (which are stored in a buffer) and we feed the network. That way the agent relives its past and improve its memory. Another reason for this task is to force the agent to release himself from oscillation, which occurs due to high correlation between some states and resulting in the same actions over and over.</p>
